# Video Studio 产品契约

> 状态：V2 演进基线  
> 适用范围：Creative Kernel、视频领域包和所有产品视图  
> 目标：把当前“能演示的开放式工作台”升级成可以长期承载真实创作项目的本地生产系统。

## 1. 产品定义

Video Studio 是一个**本地优先、AI 原生、可追溯的创作生产系统**。它不以“一次生成一个视频”为终点，而是管理从构思、稿件、结构、素材、时间线到成片的长期演进过程。

目标架构分为三层：

1. **Creative Kernel**：项目、创作单元、稿件、版本、依赖、操作、任务、资产和审计。
2. **Domain Pack**：视频叙事、广告、科普等领域的类型、规则、评估器和渲染器。
3. **Product Template**：面向具体用户目标的工作流体验，例如“剧本生成 90 秒分镜预览”。

“开放”不代表无约束。内核提供约束机制，领域包注册具体约束，产品模板组合这些约束。

## 2. 不可破坏的产品不变量

### 2.1 数据与版本

- 已经落库的 ArtifactVersion 和原始 Asset 不可原地覆盖。
- 修改已有内容必须产生新版本或语义 Operation。
- 每个派生产物必须知道自己基于哪些输入版本生成。
- 上游版本变化后，受影响的下游必须可被识别并标记为过期。
- 删除、移动、覆盖已批准内容等高风险操作不得静默执行。

### 2.2 AI 行为

- Agent 在写入前必须读取足够的权威上下文。
- Agent 不得绕过应用层直接修改数据库。
- 每次复杂执行都必须有可持久化的计划、步骤、输入、输出和结果判断。
- 生成成功不等于任务成功；结果必须经过结构校验和质量评估。
- 自动修复次数、模型成本和执行时间必须有边界。

### 2.3 任务与恢复

- 所有长任务必须持久化，进程退出后可以恢复或明确失败。
- 每个任务必须具备幂等键、attempt、timeout、取消和可观察事件。
- 用户手动重试必须得到一个干净的新执行预算，不继承旧取消标记、lease 或结果。
- 同一逻辑任务不得因重试、断线或进程恢复而重复创建业务产物。

### 2.4 用户可理解性

系统必须始终能回答：

- 现在处于什么阶段；
- AI 正在做什么；
- 使用了哪些输入；
- 产生了哪些结果；
- 哪些结果已经过期；
- 哪些操作需要确认；
- 失败后如何恢复；
- 下一步建议是什么。

用户不应理解数据库 ID、JSON Patch 或 Job payload 才能完成创作。

## 3. 首个参考产品闭环

V2 的首个 Golden Path 固定为：

```text
构思
→ 创作简报
→ 故事结构
→ 剧本
→ 镜头拆分
→ 分镜
→ 素材生成
→ 时间线
→ 预览渲染
→ 审阅与局部重生成
```

该闭环是首个打磨对象，不是永久产品边界。只有它达到生产质量后，才扩展到小说、播客或营销素材等领域。

## 4. 风险等级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| 低风险 | 创建草稿、生成候选素材、读取内容 | 可自动执行，必须可撤销或丢弃 |
| 中风险 | 批量生成、修改未批准稿件、触发较高成本任务 | 展示计划与影响范围，执行后可回滚 |
| 高风险 | 删除、结构重构、覆盖已批准内容、昂贵最终渲染 | 必须显式确认或逐条采纳 |

每次策略判断最终都应形成 `PolicyDecision`，记录动作、原因、风险、成本估计和决定。

## 5. 产品质量指标

V2 不再以页面、API、工具或测试数量作为完成标准，核心指标是：

- Golden Path 端到端任务成功率；
- 错误写入率；
- 重复产物率；
- 崩溃恢复成功率；
- 上下游过期识别准确率；
- 高风险操作拦截率；
- 用户可解释失败率；
- 单次任务成本和耗时分布。

## 6. 当前非目标

现阶段不优先建设：

- 公网多租户 SaaS；
- 大规模分布式调度；
- 更多模型渠道数量；
- 更多尚未打磨的产品页面；
- 同时支持所有创作领域；
- 为兼容早期试验数据而保留错误抽象。

本地单用户阶段继续采用 SQLite + WAL，但必须引入正式迁移、明确状态机和故障恢复测试。
